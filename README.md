# YubiVault

Локальное приложение на Rust для Windows: уникальное имя и многострочный секрет, отдельные OpenPGP-файлы, ключ шифрования на YubiKey. Имена `GitHub` и `github` различаются. Каталог имён тоже зашифрован.

## Запуск

После сборки запустите `target\release\yubivault.exe`.

1. Подключите одну YubiKey с настроенным приложением OpenPGP. Публичный сертификат и ссылка на ключ карты должны быть доступны выбранному GnuPG. Приложение не создаёт и не переносит ключи.
2. Выберите `gpg.exe` и папку хранилища. По умолчанию используются найденный GnuPG и `%LOCALAPPDATA%\YubiVault\vault`.
3. Нажмите «Создать хранилище» для новой папки или «Открыть» для существующего. Ключ определяется с карты; GnuPG может запросить PIN или касание при проверке расшифровки.
4. Добавляйте записи через интерфейс. «Сохранить» / Ctrl+S фиксирует версию; при смене записи и закрытии незаписанные правки требуют выбора «Сохранить / Отбросить / Остаться».
5. Нажатие на дату открывает соответствующую версию. Пять предыдущих версий доступны только для чтения. «Скопировать» копирует всё содержимое отображаемой версии.

При потере фокуса содержимое скрывается. При извлечении карты сеанс сбрасывается, несохранённые изменения отбрасываются. Возврат карты требует нового открытия. Черновики отсутствуют.

Для работы нужны Windows 10 2004 или новее с DWM, служба смарт-карт Windows, GnuPG 2.4 с gpg-agent, scdaemon и pinentry. Защита окна включается до открытия хранилища. Если Windows не подтверждает `WDA_EXCLUDEFROMCAPTURE`, приложение блокирует открытие. Это стандартная защита Windows; работу конкретного трекера нужно проверить на вымышленной записи. [Документация Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity).

Копирование использует исключения из истории и облачной синхронизации буфера Windows. Через 20 секунд приложение очищает свой буфер, если другая программа его не заменила; при сбросе сеанса очищает сразу. Сочетания Ctrl+C/Ctrl+X в полях используют тот же путь. [Форматы буфера Windows](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats).

## Хранение и резервирование

```text
vault/
  index.gpg             зашифрованный каталог имён и версий
  index.bak.gpg         проверенная копия каталога для восстановления
  vault.lock            блокировка второго писателя
  objects/
    <UUID>.gpg          одна зашифрованная версия одной записи
```

При сохранении новая версия полностью шифруется, записывается и сбрасывается на диск. Затем аналогично записывается новый каталог; замена `index.gpg` фиксирует изменение. Старые файлы остаются до обновления копии восстановления. Завершённое хранилище содержит текущую и пять предыдущих версий каждой записи. Прерванные записи не становятся активными.

Если основной каталог отсутствует или повреждён, приложение проверяет `index.bak.gpg` и восстанавливает его. Повреждённый исходный каталог сохраняется как `index.preserved.<UUID>.gpg`. Если не проходит проверку ни одна копия, открытие прекращается. При ошибке очистки после фиксации изменение считается сохранённым; очистка повторяется при следующем открытии или сохранении.

Для отдельной резервной копии закройте хранилище и скопируйте **всю папку**, включая `objects`, на другой носитель. Для восстановления выберите скопированную папку и откройте с той же картой. Сохранение последних версий защищает от ошибочных правок; копия на другом носителе нужна при потере диска. Копирование одного каталога недостаточно. Потеря единственной карты без другой копии ключа делает данные невосстановимыми — это принятое пользователем ограничение.

Приложение передаёт открытые данные GnuPG через каналы памяти. Расшифрованные рабочие файлы и журнал секретов не создаются. Буферы приложения обнуляются при освобождении, история отмены текстовых полей отключена. ОС и GUI могут создавать собственные копии в памяти; защиты от дампов, pagefile, гибернации и чтения памяти привилегированным процессом эта реализация не обещает. Вставленный в другое приложение секрет подчиняется правилам того приложения.

Протокол фиксации и пределы устойчивости к сбоям описаны в [ADR 0004](docs/adr/0004-catalog-commit.md). Полные требования — в [спецификации](docs/specification.md).

## Сборка и проверки

Нужны Rust 1.95+ (`x86_64-pc-windows-msvc`), Visual Studio Build Tools с C++ и Windows SDK. Скрипт подбирает Microsoft linker и SDK только для своего процесса, поскольку установленный Git может добавлять другой `link.exe` в PATH.

В PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& './scripts/cargo.ps1' -CargoArguments @('build','--release')"
powershell -NoProfile -ExecutionPolicy Bypass -Command "& './scripts/cargo.ps1' -CargoArguments @('test')"
powershell -NoProfile -ExecutionPolicy Bypass -Command "& './scripts/cargo.ps1' -CargoArguments @('clippy','--all-targets','--','-D','warnings')"
```

Тесты по умолчанию проверяют историю, регистр имён, точное содержимое, прерывания фиксации, восстановление, блокировку писателя, отмену сеанса и поздние фоновые результаты.

Дополнительные интеграционные проверки запускаются отдельно:

```powershell
# Одноразовый программный ключ в изолированном временном GNUPGHOME.
# Проверяет GnuPG, повреждение шифротекста и полное сохранение/восстановление хранилища.
powershell -NoProfile -ExecutionPolicy Bypass -Command "& './scripts/cargo.ps1' -CargoArguments @('test','actual_gpg','--','--ignored','--test-threads=1')"

# Собственное вымышленное окно; захватывается один пиксель без записи снимка.
powershell -NoProfile -ExecutionPolicy Bypass -Command "& './scripts/cargo.ps1' -CargoArguments @('test','native_capture','--','--ignored','--test-threads=1')"

# Заменяет системный буфер вымышленными данными и очищает их.
powershell -NoProfile -ExecutionPolicy Bypass -Command "& './scripts/cargo.ps1' -CargoArguments @('test','clipboard_preserves','--','--ignored','--test-threads=1')"

# Чтение метаданных подключённой карты, без PIN и расшифровки секретов.
powershell -NoProfile -ExecutionPolicy Bypass -Command "& './scripts/cargo.ps1' -CargoArguments @('test','connected_card_metadata','--','--ignored','--test-threads=1')"
```

Тестовый программный ключ доступен только в тестовой сборке. Рабочее приложение требует соответствующий ключ карты и проверяет его операцией расшифровки. Проверка отключения карты моделирует события и поздние ответы; физическое извлечение во время PIN, сохранения и редактирования проверяется вручную на вымышленном хранилище.

Результаты выполненных проверок и оставшиеся ручные действия — в [отчёте](docs/verification.md). Запуск и защиту заблокированного окна можно повторно проверить командой `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\smoke-window.ps1`.
