# Приложение для хранилища секретов

Статус: согласовано пользователем; реализация разрешена.

## Назначение

Локальное настольное приложение на Rust для Windows. Пользователь создаёт и изменяет записи через графический интерфейс, находит их по имени и копирует выбранный секрет. Расшифрованные рабочие файлы на диск не записываются.

## Записи и интерфейс

- Два поля: уникальное имя и секрет в виде свободного многострочного текста.
- Регистр имени значим: `GitHub` и `github` являются разными именами.
- Содержимое секрета сохраняется целиком, включая пробелы и переносы строк.
- Интерфейс содержит список имён с поиском, выбранную запись и список дат её предыдущих версий.
- Изменения сохраняются явно кнопкой «Сохранить» или сочетанием `Ctrl+S`; редактирование допускает отмену.
- При открытии исторической версии её поля доступны только для чтения. Доступна кнопка «Скопировать»; просмотр не восстанавливает и не изменяет текущую запись.
- Одно успешное сохранение изменённого содержимого создаёт одну новую версию. Сохранение без изменений не расходует историю.
- Сохраняются текущая версия и пять последних предыдущих версий каждой записи.
- Все записи вводятся через интерфейс приложения; автоматический импорт исходного общего GPG-файла не предусмотрен.

## Шифрование и доступ

- Каждая версия записи хранится отдельным файлом OpenPGP с непрозрачным идентификатором вместо имени записи в пути.
- Каталог имён и ссылок на версии шифруется отдельно.
- Каталог представляет собой отдельный файл `index.gpg` со списком имён, идентификаторами файлов текущих и исторических версий, датами и контрольными данными. Содержимое секретов хранится в файлах версий записей.
- При разблокировке каталог расшифровывается в память с помощью YubiKey, чтобы показать список имён и обеспечить поиск. Его расшифрованная копия на диск не записывается.
- Криптографические операции выполняет GnuPG с выбранным существующим OpenPGP-ключом; закрытый ключ пользователя находится на YubiKey.
- Приложение использует существующие настройки PIN и касания карты. Управление ключами и их резервированием остаётся за пользователем.
- Запасная карта или резервная копия ключа не являются условием работы приложения; принятое решение записано в ADR 0003.
- При обычном выборе записи расшифровывается только её выбранная версия. Каталог нужен для списка и поиска по именам.
- Данные от GnuPG принимаются в память через каналы процесса; показ происходит после успешного завершения операции и проверки её результата.
- Секреты не записываются приложением в рабочие файлы, временные файлы, журналы или диагностические сообщения. Это требование относится к файлам, создаваемым приложением; оно не является гарантией против подкачки, гибернации или чтения памяти сторонними процессами.

## Защита интерфейса и буфера обмена

- Для окон приложения включается стандартная защита Windows `SetWindowDisplayAffinity` с `WDA_EXCLUDEFROMCAPTURE`.
- Защита включается до показа секретов. Ошибка её включения блокирует показ секретных данных и сообщает о недоступности защиты.
- Глубокая интеграция с рабочим трекером не требуется. Защита ограничена поддерживаемыми механизмами захвата Windows.
- При потере фокуса показанный секрет скрывается.
- При извлечении YubiKey хранилище блокируется и сеанс сбрасывается: очищаются список имён, показанные версии и поля редактирования. Незавершённые операции не могут повторно показать данные после сброса сеанса.
- «Скопировать» копирует целиком секрет открытой текущей или исторической версии.
- Скопированный секрет исключается из истории и облачной синхронизации буфера Windows.
- Через 20 секунд буфер очищается, только если его содержимое и состояние по-прежнему относятся к последнему копированию приложения. Новое содержимое от пользователя или другой программы не удаляется.
- При сбросе сеанса собственный скопированный секрет очищается из буфера сразу с той же проверкой принадлежности.

## Безопасное сохранение

- Новая версия сначала полностью шифруется и записывается отдельным файлом; прежние версии остаются доступными.
- После записи и сброса файловых данных создаётся новый зашифрованный каталог, ссылающийся на конкретные версии.
- Переключение активного каталога является точкой фиксации изменения. Сохранение считается завершённым после успешной фиксации.
- До завершения безопасной фиксации сохраняются прежний каталог и все версии, необходимые для его восстановления.
- Очистка лишних версий и незавершённых файлов выполняется после фиксации. Файлы, нужные для оставленного состояния восстановления, не удаляются.
- В завершённом состоянии видимая история содержит пять предыдущих версий. Прерванная операция может оставить зашифрованные файлы для восстановления; такие остатки обрабатываются при следующем открытии.
- Одновременное изменение хранилища двумя экземплярами приложения блокируется.
- Подробности и ограничения согласованного протокола описаны в ADR 0004.

## Несохранённые изменения

- При смене записи или закрытии приложения подтверждение обязательно: пользователь выбирает сохранение, отказ от изменений либо отмену перехода.
- Если карта извлечена во время редактирования, сеанс немедленно сбрасывается и несохранённые изменения отбрасываются.
- Несохранённые изменения не сохраняются в виде зашифрованных черновиков ни на диске, ни в памяти.
- После возврата карты требуется новая разблокировка. Отображаются последние зафиксированные версии; прежние несохранённые правки не восстанавливаются.

## Проверка реализации

Перед использованием реальных секретов проверяются:

- Разные имена `GitHub` и `github`; отказ от повторения точно совпадающего имени.
- Сохранение и копирование многострочного содержимого с пробелами и переносами строк.
- Текущая версия плюс пять предыдущих; просмотр истории только для чтения.
- Сбои и прерывания на этапах записи версии, записи каталога, его замены и очистки; восстановление согласованного состояния.
- Блокировка второго процесса, пытающегося изменить то же хранилище.
- Ошибки GnuPG и отсутствие карты без создания расшифрованных файлов.
- Защита окна стандартными средствами захвата Windows на вымышленных секретах, включая обработку ошибки включения защиты.
- Потеря фокуса, обязательное подтверждение при смене записи и закрытии, сброс несохранённых правок при извлечении карты и новая разблокировка.
- Завершение фоновой операции после извлечения карты не показывает данные и не разблокирует сеанс.
- Очистка буфера через 20 секунд, сохранность нового чужого содержимого и исключение из истории Windows.
