# Фиксация сохранения через зашифрованный каталог

Новая версия записи создаётся отдельным зашифрованным файлом; существующие версии при этом сохраняются. После успешной записи и сброса данных создаётся новый зашифрованный каталог со ссылками на конкретные версии и их контрольными суммами. Замена активного каталога на том же томе является точкой фиксации: до неё действует прежний каталог, после неё действует новый.

Предыдущий каталог и все файлы, на которые ссылаются оставленные каталоги, сохраняются до завершения безопасной фиксации и очистки. Очистка истории и незавершённых записей выполняется после фиксации; файлы из каталога, необходимого для восстановления, не удаляются. Два экземпляра приложения не должны одновременно изменять одно хранилище.

Это добавляет протокол согласования файлов в обмен на независимое шифрование записей и скрытый каталог имён. Восстановление должно выбирать согласованный каталог, а не считать любой найденный файл завершённой записью. Гарантии Windows при ошибках замены и прерывании сохранения проверяются отдельными тестами; прежнее состояние не удаляется до подтверждённой фиксации.

Обоснование механизма каталога: [LevelDB implementation](https://github.com/google/leveldb/blob/main/doc/impl.md). Примитивы сохранения Windows: [ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew) и [FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers).
